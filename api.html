API платформы

Платформа принимает запросы HTTP(S) по адресу https://<сервер>/v1/.... Тот же API использует конфигуратор, поэтому всё, что делается в нём, можно сделать и запросом из своей программы.

Общие правила

  1. Имена полей в JSON и названия запросов пишутся в стиле camelCase:

    {
   "parentId": "...",
   "tagName": "..."
}

  2. Тело запроса — один объект JSON. Массивы передаются полями внутри него. Ответ — тоже один объект JSON.

  3. Большинство запросов работает сразу с массивами: можно создать, прочитать или изменить несколько узлов за один запрос. Подробности — в описании каждого запроса.

  4. Иерархия хранится в LDAP, поэтому имя любого узла — атрибут cn.

  5. У каждого узла есть атрибут entryUUID — неизменяемый уникальный идентификатор. Его присваивает платформа при создании узла, и он не меняется при переносе узла в другое место иерархии. Во всех запросах узлы указываются этим идентификатором (id, parentId, tagId).

  6. В имени узла допустимы любые символы. Обратную косую черту (\) и кавычки в нём нужно экранировать обратной косой чертой.

  7. При ошибке ответ содержит ключ detail. Это либо строка с описанием ошибки:

    {"detail": "описание ошибки"}

    либо список ошибок проверки запроса:

    {
  "detail": [
    {
      "type": "type_of_error",
      "loc": ["place_of_error"],
      "msg": "message",
      "input": {},
      "ctx": {"error": "name_of_error"}
    }
  ]
}
