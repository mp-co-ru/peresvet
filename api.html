API платформы

Всё, что делает конфигуратор, он делает через HTTP API платформы. Любое действие можно повторить запросом из своей программы.

Адрес и формат

API доступен по адресу https://<сервер>/v1/. Запросы и ответы — объекты JSON. Имена полей пишутся в стиле camelCase: parentId, tagId, getChildren.

Узлы модели указываются идентификаторами — значениями атрибута entryUUID вида 2e9c3c5a-0f6b-103f-8a4b-27c2f0a7d6e1. Платформа присваивает идентификатор при создании узла, и он не меняется, даже если узел перенести в другое место иерархии. Имя узла хранится в атрибуте cn и может быть любым; обратную косую черту (\) и кавычки в нём экранируют обратной косой чертой.

Большинство запросов работает с массивами: за один запрос можно прочитать, изменить или удалить несколько узлов, записать данные нескольких тегов.

Параметры запросов GET

Параметры запроса на чтение можно передать тремя способами:

  • обычными параметрами адреса — рекомендуемый способ:

    GET /v1/tags/?id=<id1>&id=<id2>&attributes=cn&attributes=prsValueTypeCode

  • одним параметром q с JSON-объектом всех ключей:

    GET /v1/tags/?q={"id":["<id1>","<id2>"],"attributes":["cn","prsValueTypeCode"]}

  • телом запроса в формате JSON. Не все HTTP-клиенты умеют отправлять тело в запросе GET, поэтому этот способ лучше не использовать.

Параметр-список (id, attributes, tagId, parentId) в адресе повторяют несколько раз. Параметр-объект (filter) передают строкой JSON.

Ответы и ошибки

Код

Когда

200

Чтение и запись данных выполнены.

201

Узел создан. В ответе — идентификатор нового узла: {"id": "<id>"}.

202

Узел изменён или удалён. Ответ — пустой объект.

403

Нет прав на действие. Бывает только в промышленной редакции, см. Точки расширения безопасности.

404

Нет такого адреса или нет данных (например, видеозаписи за период).

409

Действие противоречит состоянию модели: например, удаляется метод каталога, на который есть ссылки.

422

Запрос составлен неверно: нет обязательного поля, идентификатор не в формате GUID, нет такого узла.

424

Нет сервиса, который должен обработать запрос: например, тег не привязан ни к хранилищу, ни к методу чтения.

При ошибке ответ содержит ключ detail. Обычно это строка:

{"detail": "Узел 2e9c3c5a-0f6b-103f-8a4b-27c2f0a7d6e1 не существует."}

Некоторые запросы при ошибке формата возвращают в detail список ошибок с указанием поля. Например, удаление с идентификатором не в формате GUID:

{
  "detail": [
    {
      "type": "value_error",
      "loc": ["body", "id"],
      "msg": "Value error, id должен быть в виде GUID",
      "input": "123"
    }
  ]
}

Служебные запросы

GET /v1/ и GET /v1/version возвращают номер версии платформы:

{"version": "v0.25.0"}

Запрос GET /v1/ использует проверка источника данных в Grafana (Создание экранов в Grafana).
