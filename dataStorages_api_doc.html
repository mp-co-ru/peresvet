Хранилища данных

Какие бывают хранилища и как их настраивать, описано в разделе Хранилища данных.

Адрес — /v1/dataStorages/. Запросы те же, что у всех узлов модели (Узлы модели: общие правила). Родитель хранилища — пользовательская папка в ветке хранилищ; без parentId хранилище создаётся в корне ветки.

Тип и конфигурация

Тип хранилища задаёт prsEntityTypeCode, подключение — prsJsonConfigString:

Привязка тегов и тревог

Теги и тревоги привязывают к хранилищу полями linkedTags и linkedAlerts в запросах POST и PUT, отвязывают — полями unlinkTags и unlinkAlerts в запросе PUT:

PUT /v1/dataStorages/

{
  "id": "<id хранилища>",
  "linkedTags": [{"tagId": "<id тега>"}],
  "linkedAlerts": [{"alertId": "<id тревоги>"}],
  "unlinkTags": ["<id другого тега>"],
  "unlinkAlerts": ["<id другой тревоги>"]
}

При привязке хранилище само заводит место для данных: в PostgreSQL — таблицу t_<id тега> для тега и a_<id тревоги> для тревоги. При отвязке эта таблица удаляется вместе с историей.

Предупреждение

PostgreSQL создаёт таблицу заново при каждой привязке. Если передать в linkedTags тег, который уже привязан к этому хранилищу, его история будет стёрта. Передавайте в linkedTags только новые теги.

Тег можно привязать к нескольким хранилищам: значения пишутся в каждое. Тег типа «Видеопоток» к хранилищу истории не привязывается: только к видеоархиву.

Чтение привязок

GET /v1/dataStorages/?getLinkedTags=true&getLinkedAlerts=true добавляет к каждому хранилищу списки привязок:

{
  "data": [
    {
      "id": "<id хранилища>",
      "attributes": {"cn": ["psql"]},
      "linkedTags": [
        {"tagId": "<id тега>", "attributes": {"cn": "<id тега>", "prsStore": {"table": "t_<id тега>"}}}
      ],
      "linkedAlerts": [
        {"alertId": "<id тревоги>", "attributes": {"cn": "<id тревоги>", "prsStore": {"table": "a_<id тревоги>"}}}
      ]
    }
  ]
}

API v2 (интеграционные хранилища с операциями) описан в разделе Интеграционные хранилища.
