Точки расширения безопасности

Открытая редакция МПК-Пересвет не проверяет права: если поставщик авторизации не подключён, любое действие разрешено. Так базовая функциональность работает без внешнего сервера учётных записей, Open Policy Agent и других компонентов промышленной редакции.

Чтобы промышленная редакция или собственный продукт на базе платформы могли подключить свою авторизацию, в ядре есть точка расширения — поставщик авторизации. Раздел описывает её контракт и предназначен для разработчиков такого поставщика. Как настроить промышленную редакцию, описано в разделе Настройка безопасности промышленной редакции.

Подключение поставщика

Поставщик задаётся переменной окружения PRS_AUTH_PROVIDER в формате модуль:объект:

PRS_AUTH_PROVIDER=enterprise_security.opa_provider:OpaAuthorizationProvider

Пустое значение (по умолчанию) — встроенный поставщик AllowAllAuthorizationProvider, который разрешает всё.

Если указан класс или фабрика, платформа создаёт объект вызовом без аргументов. У объекта должен быть асинхронный метод authorize:

async def authorize(self, data: AuthorizationInput) -> AuthorizationDecision:
    ...

AuthorizationInput (модуль src.common.authorization) содержит:

  • action — проверяемое действие, см. Действия;

  • request — текущий HTTP-запрос FastAPI, если проверка идёт при обработке запроса;

  • resource — над чем выполняется действие (идентификаторы узлов, тегов и т.п.);

  • subject, environment — сведения о субъекте и окружении;

  • payload — тело запроса или сообщения.

AuthorizationDecision содержит allow (разрешено или нет), необязательную причину reason и metadata. Если поставщик вернул allow=False, HTTP API отвечает кодом 403. Причину отказа не стоит делать подробной: она может попасть к клиенту.

Контекст HTTP-запроса

Пока обрабатывается HTTP-запрос, ядро хранит объект Request в контекстной переменной. Поставщик может взять из него заголовок Authorization: Bearer ..., IP-адрес клиента, путь и метод запроса, служебные заголовки обратного прокси.

Это работает одинаково и когда сервисы запущены по отдельности, и когда платформа работает одним приложением one_app.

Внутренние сообщения RabbitMQ

В распределённой установке сервисы работают в разных контейнерах и на разных серверах и общаются через RabbitMQ. Для неё у поставщика может быть второй, необязательный метод:

async def amqp_publish_headers(self, data: AuthorizationInput) -> dict:
    ...

Отправка. Перед публикацией внутреннего сообщения ядро вызывает amqp_publish_headers с действием amqp.publish и ресурсом вида:

{
   "service": "tags_app_api",
   "routing_key": "prsTag.app_api.data_set.*",
   "reply": true
}

service — имя сервиса-отправителя из его конфигурации. Возвращённый словарь добавляется к заголовкам AMQP сообщения. Так поставщик может передать подписанный контекст безопасности (кто инициировал запрос, идентификатор запроса), не меняя тело сообщения. Встроенный поставщик возвращает пустой словарь.

Цепочки сервисов. Если сервис отправляет сообщение, обрабатывая входящее, amqp_publish_headers получает в environment.amqp_context контекст входящего сообщения: сервис-получатель, ключ маршрутизации, заголовки, reply_to и correlation_id. По нему поставщик переносит исходного пользователя и идентификатор запроса через всю цепочку:

HTTP API -> сервис A -> RabbitMQ -> сервис B -> RabbitMQ -> сервис C

Получение. До передачи входящего сообщения обработчику ядро вызывает authorize с действием amqp.consume. В resource — имя сервиса-получателя, ключ маршрутизации, reply_to и correlation_id, в environment — заголовки AMQP. Если поставщик запретил, сообщение не обрабатывается, а на запрос с ожиданием ответа (RPC) отправляется ошибка 403.

Ответы RPC проходят те же проверки: при отправке ответа вызывается amqp_publish_headers, при получении — authorize с amqp.consume. Если поставщик запретил ответ, ожидающая сторона получает ошибку 403.

Действия

Работа с узлами модели. <класс>.create, <класс>.read, <класс>.update, <класс>.delete, где класс — prsObject, prsTag, prsAlert, prsMethod, prsConnector, prsDataStorage, prsSchedule. Копирование — prsObject.copy, prsTag.copy, prsAlert.copy, prsMethod.copy, prsConnector.copy.

Пользовательская папка проверяется действием той сущности, в чьей ветке она лежит: создание папки в ветке тегов — prsTag.create с флагом "folder": true в запросе. Отдельных действий для папок нет. Право на удаление папки означает право удалить её вместе со всем содержимым: вложенные узлы удаляются каскадом, без отдельной проверки для каждого.

Данные и тревоги.

  • prsTag.data_get — чтение данных тега, в том числе видео (живой поток, снимки, записи);

  • prsTag.data_set — запись данных тега;

  • prsAlert.alarm_read, prsAlert.alarm_ack — чтение и квитирование тревог.

Коннекторы и сервисы.

  • prsConnector.connector_command — удалённые команды коннектору и управление камерой (/v1/ptz/);

  • prsConnector.link_status_read — состояние связи коннектора;

  • prsConnector.connector_log_read — журнал коннектора;

  • prsConnector.connector_command_output_read — результаты удалённых команд;

  • prsConnector.service_inventory_read — список сервисов платформы;

  • prsConnector.service_log_read, prsConnector.service_log_clear — чтение и очистка журналов сервисов.

Внутренние сообщения. amqp.publish, amqp.consume.

Для чего это нужно

Через эту точку расширения промышленная редакция подключает:

  • аутентификацию пользователей и внешних программ;

  • правила доступа по атрибутам пользователя и ресурса (ABAC/PBAC);

  • внешний сервер принятия решений, например Open Policy Agent;

  • журнал решений авторизации;

  • права, привязанные к иерархии объектов, тегов, тревог и коннекторов в LDAP.

В открытой редакции правил доступа нет, и без явно подключённого поставщика ничего не проверяется.
