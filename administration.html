Администрирование

Раздел описывает резервное копирование и восстановление установленной платформы. Все скрипты лежат в каталоге admin_scripts/.

Общие правила для всех скриптов:

  • Скрипты запускаются из корня установки — каталога, где лежат run_one_app.sh, docker/compose/ и admin_scripts/. Из другого каталога скрипт откажется работать. Исключение — справка -h или --help: она выводится откуда угодно.

  • Параметры задаются в виде --имя=значение, имена пишутся строчными буквами.

  • Архивы содержат все данные платформы, а архив контейнеров — ещё и переменные окружения с паролями. Храните их как конфиденциальные файлы.

Резервная копия всех контейнеров

Этот способ сохраняет всю Docker-установку целиком и подходит для переноса на другой сервер или аварийного восстановления. Скрипты лежат в admin_scripts/docker/:

  • running_containers_backup.sh — собирает все работающие контейнеры и их данные в один архив .tar.gz;

  • running_containers_restore.sh — разворачивает такой архив.

Скрипты берут список контейнеров из docker ps, а не из compose-файлов. Поэтому в архив попадают все работающие контейнеры, в том числе сторонние, не относящиеся к Пересвету.

Что сохраняется

  • образ каждого работающего контейнера в его текущем состоянии (снимок docker commit);

  • содержимое всех томов Docker, подключённых к этим контейнерам;

  • каталоги сервера, подключённые в контейнеры (bind mount), если не задан --no_bind_mounts=1;

  • описание контейнеров, образов, томов и сетей (вывод docker inspect);

  • команды для повторного запуска контейнеров.

Перед копированием данных скрипт останавливает контейнеры, а после — запускает их снова. Так PostgreSQL, LDAP, RabbitMQ и другие сервисы не пишут на диск во время копирования, и архив получается целостным. С параметром --skip_stop=1 контейнеры продолжают работать, но тогда данные в архиве могут оказаться несогласованными.

Создание архива

cd /путь/к/peresvet
./admin_scripts/docker/running_containers_backup.sh

Параметр

Назначение

По умолчанию

backup_dir

Каталог для архива: относительно корня установки или абсолютный путь.

backups/docker_runtime

archive_name

Имя файла архива.

docker_runtime_<дата>.tar.gz

helper_image

Образ вспомогательного контейнера, который упаковывает тома.

busybox:stable

skip_stop

1 — не останавливать контейнеры перед копированием.

0

no_bind_mounts

1 — не сохранять каталоги сервера, подключённые в контейнеры.

0

keep_committed_images

1 — не удалять временные образы-снимки после создания архива.

0

Пример с именем архива:

./admin_scripts/docker/running_containers_backup.sh \
  --archive_name=project_runtime_backup.tar.gz

Восстановление

./admin_scripts/docker/running_containers_restore.sh \
  --archive=backups/docker_runtime/project_runtime_backup.tar.gz

Что делает скрипт:

  • загружает образы из архива (docker load);

  • создаёт недостающие тома Docker;

  • если том или каталог сервера уже существует, спрашивает, перезаписать его или пропустить;

  • создаёт сети Docker из архива, если сетей с такими именами ещё нет;

  • запускает контейнеры с сохранёнными томами, портами, именем хоста, политикой перезапуска и сетями.

Параметр

Назначение

По умолчанию

archive

Обязательный. Путь к архиву running_containers_backup.sh.

—

helper_image

Образ вспомогательного контейнера, который очищает и распаковывает тома.

alpine:3.20

assume_yes

1 — перезаписывать существующие тома, каталоги и контейнеры без вопросов.

0

1 — не останавливать контейнеры, которые используют перезаписываемый том. Если том занят, этот шаг завершится ошибкой.

0

skip_containers

1 — восстановить только образы и данные, контейнеры не запускать.

0

Примечание

Восстановление возвращает сохранённое состояние контейнеров, но не заменяет compose-файлы. У сетей Docker восстанавливаются только имена. Сложные настройки сетей, например статическая адресация, сохраняются в описании внутри архива, и их нужно повторить вручную.

Резервная копия LDAP

Иерархия модели хранится в OpenLDAP. Если нужно сохранить только её, без остальных контейнеров, используйте скрипты из admin_scripts/ldap/:

  • ldap_volume_backup.sh — создаёт архив данных LDAP;

  • ldap_volume_restore.sh — восстанавливает данные из архива.

Данные OpenLDAP лежат в контейнере в каталоге /var/lib/ldap. Compose-файлы подключают его как том Docker:

  • docker/compose/docker-compose.ldap.one_app.yml — том ldap_data_one_app (стандартная поставка);

  • docker/compose/docker-compose.ldap.yml — том ldap_data.

Docker добавляет к имени тома имя проекта, например compose_ldap_data_one_app. Посмотреть фактическое имя можно командой docker volume ls | grep ldap.

Где лежат данные, скрипты по умолчанию определяют сами: они разбирают compose-файл и находят, что подключено в /var/lib/ldap у сервиса LDAP — том Docker или каталог сервера. Для этого на сервере нужен python3. Цель можно задать и явно. Приоритет такой: сначала ldap_docker_volume, затем ldap_data_dir, затем разбор compose_file.

Логические параметры (skip_stop, skip_compose_stop, assume_yes) считаются включёнными при значениях 1, true, yes, YES. Любое другое значение, в том числе пустое, означает «выключено».

Создание архива

По умолчанию скрипт останавливает сервис ldap через docker compose, упаковывает данные в backups/ldap/ и снова запускает сервис:

cd /путь/к/peresvet
./admin_scripts/ldap/ldap_volume_backup.sh

С явными параметрами:

./admin_scripts/ldap/ldap_volume_backup.sh \
  --compose_file=docker/compose/docker-compose.ldap.one_app.yml \
  --compose_project_name=myproj \
  --backup_dir=backups/ldap

backup_dir

Каталог для архивов: относительно корня установки или абсолютный путь.

ldap_docker_volume

Явно заданное полное имя тома Docker с данными LDAP.

Явно заданный каталог сервера с данными LDAP. Не используется, если задан ldap_docker_volume.

Восстановление

Скрипт останавливает сервис LDAP, очищает каталог данных, распаковывает архив и снова запускает сервис. Перед перезаписью он спрашивает подтверждение. Без вопросов:

cd /путь/к/peresvet
./admin_scripts/ldap/ldap_volume_restore.sh \
  --assume_yes=1 \
  --archive=backups/ldap/ИМЯ_АРХИВА.tar.gz

Предупреждение

Восстанавливайте архив только в такую же установку: с тем же образом и той же схемой LDAP. В архив попадают только данные из /var/lib/ldap, а настройки slapd и схема зашиты в образ при сборке.

Отладка определения тома

Том или каталог данных находит вспомогательный скрипт admin_scripts/ldap/resolve_ldap_storage.py. Shell-скрипты вызывают его сами; вручную он нужен только для отладки. Его аргументы позиционные:

  1. путь к compose-файлу;

  2. имя проекта для docker compose -p (необязательно; пустая строка — без -p);

  3. имя сервиса (необязательно, по умолчанию ldap).

Переменная окружения RESOLVE_CWD задаёт рабочий каталог для docker compose. Скрипт печатает одну строку из двух полей через табуляцию: volume и полное имя тома Docker либо bind и абсолютный путь на сервере.
