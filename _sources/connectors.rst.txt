Коннекторы
~~~~~~~~~~
Типичным средством поставки данных в платформу являются коннекторы.

Коннектор - специализированная программа, предназначенная для чтения данных с какого-либо источника и отправки их в платформу.

Предполагается, но не требуется, что один коннектор работает только с одним источником данных.

Общая логика работы коннекторов реализована в базовом модуле для создания коннекторов
`prs-connector-core <https://github.com/mp-co-ru/prs-connector-core>`__ и описана в документации к нему.

Для того, чтобы коннектор мог работать с платформой, в платформе должна быть создана запись,
содержащая настройки коннектора и список привязанных к нему тегов, для которых коннектор должен читать данные
из источника данных.

Связь по MQTT и коды качества тегов
-----------------------------------
Коннекторы подключаются к платформе по протоколу MQTT. Сообщения коннекторов поступают в платформу
через мост RabbitMQ MQTT plugin → обменник AMQP (обменник ``peresvet``).

Платформа отслеживает наличие связи с коннекторами и при определённых событиях записывает во все
теги, привязанные к коннектору, значение ``null`` с соответствующим кодом качества. Это позволяет
различать «нет данных» из-за потери связи, восстановления связи и т.п.

Коды качества
~~~~~~~~~~~~~

* **100** — потеря связи с коннектором. Платформа пишет ``null`` с кодом 100 во все
  привязанные теги при **любом** разрыве MQTT-сессии на брокере:

  * событие RabbitMQ ``connection.closed`` (обменник ``amq.rabbitmq.event``) — штатный
    DISCONNECT, обрыв TCP, таймаут keepalive, закрытие со стороны брокера.
    Платформа получает эти события по **AMQP** (``broker.amqp_url``), MQTT-порт брокера
    ей для этого не нужен: коннектор ходит на MQTT, а сервис ``connectors_mqtt_app``
    слушает события сессий на том же брокере через уже установленное AMQP-соединение.
    Сессия коннектора узнаётся по протоколу ``MQTT`` в заголовках события и ClientId.
  * Last Will and Testament, если брокер дополнительно публикует will (нештатный обрыв).

  Повторная запись 100 с тем же качеством в теги отсекается правилами ``data_set``.
  Чтобы сопоставить сессию брокера с коннектором, MQTT **ClientId должен быть UUID
  коннектора** (так делает `prs-connector-core <https://github.com/mp-co-ru/prs-connector-core>`__).

* **101** — восстановление связи с коннектором. Записывается при **первом запросе конфигурации**
  новой сессии (сообщение ``conn2prs`` / ``getConfig``), **до** ответа
  ``prsConnector.full_configuration``. Во все привязанные к коннектору теги пишется ``null``
  с кодом качества 101; платформа ждёт подтверждения записи в TagsApp и только после этого
  публикует полную конфигурацию в ``prs2conn/<connector_id>``. Повторный запрос конфигурации,
  пока сессия считается онлайн, код 101 не дублирует. Потеря связи (100, в т.ч. LWT) снимает
  сессию, следующий ``getConfig`` снова пишет 101.

Порядок точек в истории тегов при обрыве и восстановлении MQTT-сессии:

1. ``null``, качество **100** — потеря MQTT-сессии на брокере (``connection.closed`` и/или LWT
   ``prsConnector.connection_lost.<id>``).
2. Буфер коннектора с метками времени **до** восстановления — коннектор может слать его сразу
   после MQTT CONNECT; эти точки стоят в истории **перед** 101.
3. ``null``, качество **101** — платформа, на запросе конфигурации, до ``full_configuration``.
4. Текущие значения с источника — **после** разбора ``full_configuration``. Коннектор обязан
   прочитать все привязанные теги на источнике и отправить их в ``data_set``, даже если значение
   не изменилось. Иначе, если источник молчит, текущим останется ``null/101``.

Контракт коннектора (`prs-connector-core <https://github.com/mp-co-ru/prs-connector-core>`__):

* Сразу после установки MQTT-связи можно отправлять **накопленный буфер** (метки ``x`` до
  восстановления). Это не замена текущему значению после сессии.
* Запрос конфигурации — после MQTT CONNECT. Живой опрос источника и отправка текущих значений
  (в том числе повторов) — **только после** получения и разбора ``prsConnector.full_configuration``.
  Не сбрасывать lastValue и не слать «текущие» точки с новыми метками до конфига: иначе они
  окажутся в истории раньше 101, и текущим снова станет ``null/101``.

Last Will and Testament (LWT)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Чтобы при нештатном отключении коннектора (обрыв сети, аварийное завершение процесса) брокер
дополнительно опубликовал явное сообщение в шину, коннектор при CONNECT настраивает Last Will.
Основной путь записи **100** — событие ``connection.closed`` на брокере (включая штатный DISCONNECT
и keepalive). LWT дублирует тот же обработчик, если will сработал.

* **Топик (Will topic):** ``prsConnector/connection_lost/<connector_id>``, где ``<connector_id>`` —
  UUID коннектора в платформе (тот же, что используется в топиках ``conn2prs/<connector_id>``
  и ``prs2conn/<connector_id>``).

* **Тело (Will payload):** JSON-объект ``{"id": "<connector_id>"}``.

При срабатывании LWT брокер публикует это сообщение в топик; через привязку обменника ``amq.topic``
к ``peresvet`` (routing key ``prsConnector.connection_lost.*``) сообщение попадает в платформу,
сервис ``connectors_mqtt_app`` обрабатывает его и записывает во все теги данного коннектора
значение ``null`` с кодом качества 100.

Базовый класс коннекторов `prs-connector-core <https://github.com/mp-co-ru/prs-connector-core>`__
уже настраивает LWT при подключении к платформе по MQTT; при разработке коннектора на его основе
дополнительная настройка не требуется.

Удалённые команды коннектору
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Через HTTP API ``POST /v1/connectors_app/`` (см. сервис ``connectors_app_api``) можно передать коннектору
поле ``command.lines``: каждая непустая строка выполняется на стороне коннектора в shell (базовый класс
`prs-connector-core <https://github.com/mp-co-ru/prs-connector-core>`__). Результат (код выхода, stdout, stderr)
публикуется в платформу по MQTT отдельным действием ``prsConnector.command_output`` (не смешивается с
``prsConnector.log_line``). Сервис ``connectors_mqtt_app`` хранит буфер результатов; список последних записей:
``GET /v1/connectors_app/command_output_tail?id=<uuid>``.
