.. _administration:

Администрирование
=================

Раздел описывает резервное копирование и восстановление установленной
платформы. Все скрипты лежат в каталоге ``admin_scripts/``.

Какой способ выбрать
--------------------

.. list-table::
   :header-rows: 1
   :widths: 44 56

   * - Задача
     - Способ
   * - Перенести установку на другой сервер или восстановить её
       после аварии целиком
     - `Резервная копия всех контейнеров`_
   * - Регулярно сохранять данные платформы: модель, историю тегов,
       экраны Grafana
     - `Резервная копия данных`_, все три хранилища сразу
   * - Сохранить или вернуть что-то одно, например только модель
     - `Резервная копия данных`_, отдельный скрипт

Общие правила
-------------

* Скрипты запускаются **из корня установки** — каталога, где лежат
  ``run_one_app.sh``, ``docker/compose/`` и ``admin_scripts/``.
  Из другого каталога скрипт откажется работать. Справку ``-h``
  или ``--help`` можно вывести откуда угодно.
* Параметры задаются в виде ``--имя=значение``, имена пишутся строчными
  буквами.
* Логические параметры включаются значениями ``1``, ``true``, ``yes``,
  ``YES``. Любое другое значение, в том числе пустое, означает
  «выключено».
* Архивы содержат все данные платформы, а архив контейнеров — ещё
  и переменные окружения с паролями. Храните их как конфиденциальные файлы.

.. _administration_docker_runtime_backup:

Резервная копия всех контейнеров
--------------------------------

Этот способ сохраняет всю Docker-установку целиком. Скрипты лежат
в ``admin_scripts/docker/``:

* ``running_containers_backup.sh`` — собирает все работающие контейнеры
  и их данные в один архив ``.tar.gz``;
* ``running_containers_restore.sh`` — разворачивает такой архив.

Список контейнеров скрипты берут из ``docker ps``, а не из compose-файлов.
Поэтому в архив попадают все работающие контейнеры сервера, в том числе
не относящиеся к Пересвету.

Что сохраняется
~~~~~~~~~~~~~~~

* образ каждого работающего контейнера в его текущем состоянии
  (снимок ``docker commit``);
* содержимое всех томов Docker, подключённых к этим контейнерам;
* каталоги сервера, подключённые в контейнеры (bind mount), если не задан
  ``--no_bind_mounts=1``;
* описание контейнеров, образов, томов и сетей (вывод ``docker inspect``);
* команды для повторного запуска контейнеров.

Перед копированием данных скрипт останавливает контейнеры, а после —
запускает их снова. Так PostgreSQL, LDAP, RabbitMQ и другие сервисы не пишут
на диск во время копирования, и архив получается целостным. С параметром
``--skip_stop=1`` контейнеры продолжают работать, но тогда данные в архиве
могут оказаться несогласованными.

Создание архива
~~~~~~~~~~~~~~~

.. code:: sh

   cd /путь/к/peresvet
   ./admin_scripts/docker/running_containers_backup.sh \
     --archive_name=project_runtime_backup.tar.gz

.. list-table::
   :header-rows: 1
   :widths: 26 54 20

   * - Параметр
     - Назначение
     - По умолчанию
   * - ``backup_dir``
     - Каталог для архива: относительно корня установки или абсолютный путь.
     - ``backups/docker_runtime``
   * - ``archive_name``
     - Имя файла архива.
     - ``docker_runtime_<дата>.tar.gz``
   * - ``helper_image``
     - Образ вспомогательного контейнера, который упаковывает тома.
     - ``busybox:stable``
   * - ``skip_stop``
     - ``1`` — не останавливать контейнеры перед копированием.
     - ``0``
   * - ``no_bind_mounts``
     - ``1`` — не сохранять каталоги сервера, подключённые в контейнеры.
     - ``0``
   * - ``keep_committed_images``
     - ``1`` — не удалять временные образы-снимки после создания архива.
     - ``0``

Восстановление
~~~~~~~~~~~~~~

.. code:: sh

   ./admin_scripts/docker/running_containers_restore.sh \
     --archive=backups/docker_runtime/project_runtime_backup.tar.gz

Скрипт:

#. загружает образы из архива (``docker load``);
#. создаёт недостающие тома Docker;
#. если том или каталог сервера уже существует, спрашивает, перезаписать
   его или пропустить;
#. создаёт сети Docker из архива, если сетей с такими именами ещё нет;
#. запускает контейнеры с сохранёнными томами, портами, именем хоста,
   политикой перезапуска и сетями.

.. list-table::
   :header-rows: 1
   :widths: 26 54 20

   * - Параметр
     - Назначение
     - По умолчанию
   * - ``archive``
     - **Обязательный.** Путь к архиву ``running_containers_backup.sh``.
     - —
   * - ``helper_image``
     - Образ вспомогательного контейнера, который очищает и распаковывает
       тома.
     - ``alpine:3.20``
   * - ``assume_yes``
     - ``1`` — перезаписывать существующие тома, каталоги и контейнеры
       без вопросов.
     - ``0``
   * - ``skip_stop``
     - ``1`` — не останавливать контейнеры, которые используют
       перезаписываемый том. Если том занят, этот шаг завершится ошибкой.
     - ``0``
   * - ``skip_containers``
     - ``1`` — восстановить только образы и данные, контейнеры не запускать.
     - ``0``

.. note::

   Восстановление возвращает сохранённое состояние контейнеров, но не
   заменяет compose-файлы. У сетей Docker восстанавливаются только имена.
   Сложные настройки сетей, например статическая адресация, сохраняются
   в описании внутри архива, и их нужно повторить вручную.

.. _administration_ldap_backup:

Резервная копия данных
----------------------

Данные платформы лежат в трёх хранилищах. У каждого есть своя пара
скриптов — создание архива и восстановление из него:

.. list-table::
   :header-rows: 1
   :widths: 22 30 48

   * - Что хранится
     - Каталог в контейнере
     - Скрипты
   * - Модель (иерархия) в OpenLDAP
     - ``/var/lib/ldap``
     - ``admin_scripts/ldap/ldap_volume_backup.sh``,
       ``admin_scripts/ldap/ldap_volume_restore.sh``
   * - История тегов и эпизоды тревог в PostgreSQL
     - ``/var/lib/postgresql/data``
     - ``admin_scripts/historian/historian_volume_backup.sh``,
       ``admin_scripts/historian/historian_volume_restore.sh``
   * - Экраны и настройки Grafana
     - ``/var/lib/grafana``
     - ``admin_scripts/grafana/grafana_volume_backup.sh``,
       ``admin_scripts/grafana/grafana_volume_restore.sh``

Все три хранилища сразу
~~~~~~~~~~~~~~~~~~~~~~~

Скрипт ``admin_scripts/backup_storages.sh`` по очереди вызывает три
скрипта создания архива. Архивы попадают в ``backups/ldap/``,
``backups/historian/`` и ``backups/grafana/``:

.. code:: sh

   cd /путь/к/peresvet
   ./admin_scripts/backup_storages.sh

Восстановление — ``admin_scripts/restore_storages.sh`` с путями ко всем
трём архивам:

.. code:: sh

   ./admin_scripts/restore_storages.sh \
     --ldap_archive=backups/ldap/<архив>.tar.gz \
     --historian_archive=backups/historian/<архив>.tar.gz \
     --grafana_archive=backups/grafana/<архив>.tar.gz

Параметры ``--skip_ldap=1``, ``--skip_historian=1`` и ``--skip_grafana=1``
пропускают хранилище; тогда его архив указывать не нужно. Общие параметры
``compose_project_name``, ``skip_stop``, ``skip_compose_stop``, а при
восстановлении ещё ``assume_yes`` и ``restore_helper_image``, передаются
всем трём скриптам.

Каждое хранилище отдельно
~~~~~~~~~~~~~~~~~~~~~~~~~

По умолчанию скрипт создания архива останавливает сервис через
``docker compose``, упаковывает каталог данных и снова запускает сервис:

.. code:: sh

   ./admin_scripts/ldap/ldap_volume_backup.sh

Скрипт восстановления останавливает сервис, очищает каталог данных,
распаковывает архив и снова запускает сервис. Перед перезаписью он
спрашивает подтверждение; ``--assume_yes=1`` отключает вопрос:

.. code:: sh

   ./admin_scripts/ldap/ldap_volume_restore.sh \
     --assume_yes=1 \
     --archive=backups/ldap/<архив>.tar.gz

Скрипты PostgreSQL и Grafana вызываются так же.

Где лежат данные, скрипты определяют сами: разбирают compose-файл
и находят, что подключено в каталог данных сервиса — том Docker или
каталог сервера. Для этого на сервере нужен ``python3``. Цель можно
задать и явно, параметром тома или каталога (см. таблицу ниже).
Приоритет: явный том, затем явный каталог, затем разбор compose-файла.

Docker добавляет к имени тома имя проекта, например
``compose_ldap_data_one_app``. Фактические имена показывает команда
``docker volume ls``.

Параметры
~~~~~~~~~

Параметры у трёх пар скриптов одинаковые, различаются только имена
некоторых из них и значения по умолчанию:

.. list-table::
   :header-rows: 1
   :widths: 28 24 24 24

   * - Параметр
     - LDAP
     - PostgreSQL
     - Grafana
   * - ``compose_file``
     - ``docker/compose/``
       ``docker-compose.ldap.one_app.yml``
     - ``docker/compose/``
       ``docker-compose.postgresql.data_in_volume.yml``
     - ``docker/compose/``
       ``docker-compose.grafana.yml``
   * - Имя сервиса в compose-файле
     - ``ldap_service=ldap``
     - ``postgres_service=psql``
     - ``grafana_service=grafana``
   * - ``backup_dir`` (только создание)
     - ``backups/ldap``
     - ``backups/historian``
     - ``backups/grafana``
   * - Явно заданный том Docker
     - ``ldap_docker_volume``
     - ``historian_docker_volume``
     - ``grafana_docker_volume``
   * - Явно заданный каталог сервера
     - ``ldap_data_dir``
     - ``historian_data_dir``
     - ``grafana_data_dir``

Общие для всех:

.. list-table::
   :header-rows: 1
   :widths: 26 74

   * - Параметр
     - Назначение
   * - ``archive``
     - **Обязательный при восстановлении.** Путь к архиву: относительно
       корня установки или абсолютный.
   * - ``compose_project_name``
     - Имя проекта Docker Compose (ключ ``-p``). Пусто — как у
       ``docker compose`` без ``-p``, с учётом переменной
       ``COMPOSE_PROJECT_NAME``.
   * - ``backup_helper_image``
     - Образ вспомогательного контейнера, который упаковывает данные.
       По умолчанию ``busybox:stable``.
   * - ``restore_helper_image``
     - Образ вспомогательного контейнера, который очищает и распаковывает
       данные (в нём нужны ``find`` и ``tar``). По умолчанию ``alpine:3.20``.
   * - ``assume_yes``
     - ``1`` — не спрашивать подтверждение перед перезаписью.
   * - ``skip_compose_stop``
     - ``1`` — не вызывать ``docker compose stop/start`` для сервиса.
       Тогда останавливаются контейнеры, которые используют том
       (если не задан ``skip_stop=1``).
   * - ``skip_stop``
     - ``1`` — не останавливать и контейнеры, которые используют том.
       Имеет смысл вместе с ``skip_compose_stop=1``. При создании архив
       может оказаться несогласованным, при восстановлении скрипт
       завершится ошибкой, если том занят: писать в работающую базу
       он не будет.

.. warning::

   Восстанавливайте архив только в такую же установку: с теми же
   образами и той же схемой LDAP. В архив попадает только каталог данных,
   а настройки ``slapd``, схема LDAP и версия PostgreSQL зашиты в образы.

Отладка определения тома
~~~~~~~~~~~~~~~~~~~~~~~~

Том или каталог данных находят вспомогательные скрипты
``resolve_ldap_storage.py``, ``resolve_historian_storage.py`` и
``resolve_grafana_storage.py`` в тех же каталогах. Shell-скрипты вызывают
их сами; вручную они нужны только для отладки. Аргументы позиционные:

#. путь к compose-файлу;
#. имя проекта для ``docker compose -p`` (необязательно; пустая строка —
   без ``-p``);
#. имя сервиса (необязательно, по умолчанию как в таблице выше).

Переменная окружения ``RESOLVE_CWD`` задаёт рабочий каталог для
``docker compose``. Скрипт печатает одну строку из двух полей через
табуляцию: ``volume`` и полное имя тома Docker либо ``bind`` и абсолютный
путь на сервере.
