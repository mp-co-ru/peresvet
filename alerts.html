Тревоги

Как работают тревоги, описано в разделе Тревоги. Здесь — запросы к ним. Узлы тревог создаются и меняются запросами /v1/alerts/, эпизоды читаются и квитируются запросами /v1/alarms/.

Узлы тревог

Адрес — /v1/alerts/. Запросы те же, что у всех узлов модели (Узлы модели: общие правила), включая копирование POST /v1/alerts/copy.

Родитель тревоги — всегда тег, поэтому parentId при создании обязателен. При копировании parentId — тег, под которым появится копия.

Условие тревоги задаётся в prsJsonConfigString:

Ключ

Смысл

По умолчанию

value

Порог.

10

high

true — тревога, пока значение тега >= value; false — пока значение < value.

true

autoAck

true — квитировать в момент срабатывания.

true

Пример — тревога «Перегрев» при температуре 30 °C и выше с ручным квитированием:

POST /v1/alerts/

{
  "parentId": "<id тега>",
  "attributes": {
    "cn": "Перегрев",
    "prsJsonConfigString": {"value": 30, "high": true, "autoAck": false}
  }
}

Чтобы тревога сохраняла эпизоды, привяжите её к хранилищу (Хранилища данных, поле linkedAlerts).

Чтение эпизодов

GET /v1/alarms/

Параметр

Смысл

По умолчанию

parentId

Объект, тег, тревога или пользовательская папка. Можно передать несколько.

—

alertId

Идентификатор тревоги. То же, что parentId с этим идентификатором.

—

getChildren

Учитывать вложенные объекты и папки.

false

fired

Режим ответа, см. ниже.

true

start

Нижняя граница метки срабатывания.

—

finish

Момент, на который смотрят состояние, или верхняя граница метки срабатывания.

текущий момент

count

Сколько последних эпизодов вернуть по каждой тревоге, от 1 до 500.

—

format

Метки времени строками ISO 8601 в часовом поясе сервера. Без него — целые числа микросекунд.

false

Метки start и finish задаются так же, как в запросах исторических данных: целым числом микросекунд или строкой ISO 8601.

Режимы ответа

Ключи

Что возвращается

fired=true (по умолчанию)

Эпизоды, активные в момент finish: не больше одной строки на тревогу. Со start — только эпизоды, сработавшие не раньше start. count не учитывается.

fired=false без start и count

Состояние каждой тревоги в момент finish: ровно одна строка на тревогу — последний эпизод, начавшийся к этому моменту, даже если он уже закончился и квитирован. У тревоги, которая ещё ни разу не срабатывала, все три метки пустые.

fired=false со start или count

Список эпизодов, сработавших в промежутке от start до finish, от новых к старым. Без count — не больше 500 на тревогу.

Метки, которые наступили позже finish, в ответе пустые: эпизод показывается таким, каким он был в момент finish.

Ответ

{
  "data": [
    {
      "id": "<id тревоги>",
      "cn": "Перегрев",
      "description": "",
      "tagId": "<id тега>",
      "fired": "2026-11-17T19:10:58.571809+03:00",
      "finish": "2026-11-17T19:12:16.078625+03:00",
      "acked": null
    }
  ]
}

  • id, cn, description — тревога;

  • tagId — тег, к которому она относится;

  • fired, finish, acked — срабатывание, пропадание и квитирование эпизода. Пустое значение — null.

Состояние эпизода по меткам описано в разделе Тревоги.

Примеры

# активные тревоги объекта
GET /v1/alarms/?parentId=<id объекта>

# активные тревоги двух объектов и всех вложенных в них
GET /v1/alarms/?parentId=<id1>&parentId=<id2>&getChildren=true

# активна ли тревога сейчас
GET /v1/alarms/?alertId=<id тревоги>

# состояние всех тревог объекта, в том числе неактивных
GET /v1/alarms/?parentId=<id объекта>&fired=false

# состояние всех тревог объекта на 1 января 2026
GET /v1/alarms/?parentId=<id объекта>&fired=false&finish=2026-01-01T00:00:00Z

# 10 последних эпизодов каждой тревоги объекта
GET /v1/alarms/?parentId=<id объекта>&fired=false&count=10

# все эпизоды объекта, сработавшие с 1 по 10 января 2026
GET /v1/alarms/?parentId=<id объекта>&fired=false&start=2026-01-01T00:00:00Z&finish=2026-01-10T00:00:00Z

# тревоги объекта, активные 10 января 2026 и сработавшие не раньше 1 января
GET /v1/alarms/?parentId=<id объекта>&start=2026-01-01T00:00:00Z&finish=2026-01-10T00:00:00Z

История эпизодов и состояние на прошлый момент читаются из хранилища. Если тревога не привязана к хранилищу, доступно только текущее состояние.

Квитирование

PUT /v1/alarms/

{"id": "<id тревоги>", "x": "2026-11-17T19:15:00+03:00"}

x — момент квитирования, необязательный: без него берётся текущий момент. Квитируется последний эпизод тревоги, если он ещё не квитирован. Квитированный эпизод и тревога, которая ни разу не срабатывала, остаются без изменений. Ответ 200.

Чего не делает /v1/data/

Тревога — не тег, у неё нет ряда значений. Запрос GET /v1/data/ с идентификатором тревоги вернёт ошибку 422 с подсказкой читать события через GET /v1/alarms/.

Сообщения для сервисов

Этот раздел нужен тем, кто пишет свой сервис платформы. Сервис тревог публикует в RabbitMQ (обменник peresvet) три сообщения:

  • prsAlert.app.alarm_on.<id тревоги> — срабатывание;

  • prsAlert.app.alarm_off.<id тревоги> — пропадание;

  • prsAlert.app.alarm_acked.<id тревоги> — квитирование.

Тело у всех трёх одинаковое: {"alertId": "<id тревоги>", "x": <метка в микросекундах>}. На эти сообщения подписаны хранилища данных (запись эпизодов) и сервис методов (запуск методов, для которых тревога — инициатор). Новый сервис может подписаться на них так же.
