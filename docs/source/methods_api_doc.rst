Методы
~~~~~~

Как устроены методы, их типы и источники параметров, описано в разделе
:doc:`methods`. Здесь — запросы к узлам методов.

Адрес — ``/v1/methods/``. Запросы те же, что у всех узлов модели
(:doc:`api_nodes`), с дополнительными полями.

Где лежит метод
---------------

* **Метод тега или тревоги** — ``parentId`` равен идентификатору тега
  или тревоги. Это либо самостоятельный метод, либо ссылка на определение
  из каталога.
* **Определение в каталоге** — ``parentId`` равен идентификатору папки
  каталога или не задан (корень каталога «Методы»).

Атрибуты
--------

.. list-table::
   :header-rows: 1
   :widths: 26 74

   * - Атрибут
     - Смысл
   * - ``prsMethodAddress``
     - Адрес функции в исполнителе, например ``prs.stdlib.add``.
       У ссылки на каталог адрес берётся из определения.
   * - ``prsEntityTypeCode``
     - Тип метода: ``0`` — вычислительный, ``1`` — чтение, ``2`` — запись,
       ``3`` — действие при чтении, ``4`` — действие при записи.
       По умолчанию ``0``. У определения в каталоге всегда ``0``.
   * - ``prsCatalogMethodId``
     - Идентификатор определения в каталоге — у ссылки. То же можно
       передать полем ``catalogMethodId`` рядом с ``attributes``.
   * - ``prsVariadic``
     - У определения в каталоге: ``true`` — произвольное число параметров,
       список задаёт каждая ссылка.

Поля запроса
------------

Рядом с ``attributes`` в запросах создания и изменения передают:

.. list-table::
   :header-rows: 1
   :widths: 20 80

   * - Поле
     - Смысл
   * - ``initiatedBy``
     - Список идентификаторов тегов, расписаний и тревог, события которых
       запускают вычислительный метод.
   * - ``alertEvents``
     - Для тревог из ``initiatedBy``: какие события запускают метод.
       Ключ — идентификатор тревоги, значение — непустой список из
       ``alarm_on`` (срабатывание), ``alarm_off`` (пропадание),
       ``alarm_acked`` (квитирование). Тревога без ключа запускает метод
       только при срабатывании.
   * - ``parameters``
     - Список параметров. У каждого — ``attributes``: ``cn`` (имя),
       ``prsIndex`` (порядковый номер аргумента), ``prsJsonConfigString``
       (источник значения, см. :doc:`methods`). У параметра определения
       в каталоге вместо источника задают ``prsValueTypeCode``: ``1`` —
       целое, ``2`` — вещественное, ``3`` — строка, ``4`` — JSON.

.. warning::

   Коды типов параметров (``1``–``4``) не совпадают с кодами типов
   значений тега (``0``, ``1``, ``2``, ``4``…).

В запросе ``PUT`` поля ``initiatedBy`` и ``parameters`` заменяют
прежние списки целиком. Если поле не передать, список не меняется.

Пример — метод тега, который пересчитывается при каждом новом значении
двух тегов и складывает их:

.. code-block:: text

   POST /v1/methods/

.. code-block:: json

   {
     "parentId": "<id тега-результата>",
     "attributes": {
       "cn": "Сумма",
       "prsMethodAddress": "sum",
       "prsEntityTypeCode": 0
     },
     "initiatedBy": ["<id тега A>", "<id тега B>"],
     "parameters": [
       {"attributes": {"cn": "a", "prsIndex": 1, "prsJsonConfigString": {"request": {"tagId": ["<id тега A>"]}}}},
       {"attributes": {"cn": "b", "prsIndex": 2, "prsJsonConfigString": {"request": {"tagId": ["<id тега B>"]}}}}
     ]
   }

Чтение
------

В ответе ``GET /v1/methods/`` у каждого метода, кроме ``attributes``, есть
поля ``initiatedBy``, ``alertEvents`` (если набор событий задан явно)
и ``parameters``. У определения в каталоге есть ещё ``parameterCount`` —
число параметров.

Копирование и удаление
----------------------

``POST /v1/methods/copy`` принимает ``sourceId`` и ``parentId``. Метод
тега или тревоги копируется под тег или тревогу, определение — внутри
каталога. Определение каталога под тег или тревогу не копируется (ответ
``422``): для этого создают ссылку.

Определение, на которое есть ссылки, и папку с таким определением удалить
нельзя: ответ ``409``.

Загрузка описания каталога
--------------------------

``POST /v1/methods/description``

.. code-block:: json

   {
     "yaml": "<текст описания>",
     "parentId": "<id папки каталога>",
     "probe": true
   }

* ``yaml`` — описание папок и методов (формат — в разделе
  :ref:`methods_yaml`);
* ``parentId`` — папка каталога, куда загрузить описание. Пусто —
  корень каталога;
* ``probe`` — после загрузки пробно вызвать каждый метод с аргументами
  из описания.

В ответе перечислено, какие папки и методы созданы, и результаты пробных
вызовов.
