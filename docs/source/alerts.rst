Тревоги
~~~~~~~

Состояние тревоги
-----------------

Тревога описывается конфигурацией тега

.. code-block:: json

   {"high": true, "value": 90, "autoAck": false}

При ``high: true`` тревога активна, пока значение тега больше или равно
``value``. При ``high: false`` — пока значение меньше ``value``.
``autoAck: true`` квитирует тревогу в момент срабатывания.

События пишутся в таблицу хранилища ``a_<id тревоги>``:

* ``x`` — метка срабатывания;
* ``cx`` — метка квитирования;
* ``e`` — метка пропадания.

Сервис тревог публикует три сообщения с плоским телом
``{"alertId": "<id>", "x": <микросекунды>}``:

* ``prsAlert.app.alarm_on.<id>``
* ``prsAlert.app.alarm_off.<id>``
* ``prsAlert.app.alarm_acked.<id>``

Хранилище отвечает на ``prsAlert.app.alarm_state.<id>`` последней строкой
этой таблицы. После перезапуска сервиса тревог кэш восстанавливается из неё.

Список и квитирование
---------------------

``GET /v1/alarms/`` читает алярмы. ``parentId`` — объект, тег, сама тревога
или список таких узлов. ``getChildren=true`` включает дочерние объекты.

Без ``parentId`` и без ``getChildren`` возвращаются алярмы объектов
верхнего уровня и всех тегов из папки «Теги». Без ``parentId``, но с
``getChildren=true`` — алярмы всей ветки объектов и той же папки «Теги».
Так кружки в дереве берёт панель Grafana: ``getChildren=true`` и
``fired=false``, без ``parentId``.

``fired=true`` (значение по умолчанию) — эпизод, который был активен
в момент ``finish``. ``finish`` по умолчанию — текущее время. Ключ
``count`` при ``fired`` не используется. ``start`` оставляет только те
из них, чей старт не раньше этой метки.

``fired=false`` без ``start`` и без ``count`` — состояние каждой тревоги
на момент ``finish``: один ряд, последний эпизод, уже начавшийся к этому
моменту. Если он успел закончиться и быть квитирован, в ряде остаются
его ``fired``, ``finish`` и ``acked``. Пустые метки — только у тревоги,
которая к этому моменту ещё не начиналась.
``fired=false`` вместе со ``start`` или ``count`` — список срабатываний.
``start`` и ``finish`` ограничивают метку старта, ``count`` — сколько
последних эпизодов вернуть по каждой тревоге (не больше 500).

Без ``format`` метки — целые микросекунды. С ``format=true`` — строки
местного времени ISO 8601. Параметр ``alertId`` означает то же, что
``parentId`` с идентификатором тревоги.

.. code-block:: text

   GET /v1/alarms/?parentId=<id объекта>&getChildren=true&format=true

.. code-block:: json

   {"data": [{
     "id": "<id тревоги>",
     "cn": "Высокий уровень",
     "description": "",
     "tagId": "<id тега>",
     "fired": "2026-11-16T16:25:32.429572+03:00",
     "finish": null,
     "acked": null
   }]}

Примеры запросов. Идентификаторы ниже — примеры. Несколько
``parentId`` в строке — это список узлов. ``fired`` и ``getChildren``
пишутся как ``true`` и ``false``. Пустой запрос — ключи по умолчанию:
``fired=true``, ``finish`` равен текущему времени.

Все активные алярмы объектов верхнего уровня и всех тегов из папки «Теги»:

.. code-block:: text

   GET /v1/alarms/

Активные алярмы объекта:

.. code-block:: text

   GET /v1/alarms/?parentId=123e4567-e89b-12d3-a456-426614174000

Состояние всех тревог объекта на текущий момент. ``fired=false`` без
``start`` и без ``count`` даёт один ряд на тревогу, в том числе неактивную:

.. code-block:: text

   GET /v1/alarms/?parentId=123e4567-e89b-12d3-a456-426614174000&fired=false

По 10 последних записей по каждой тревоге объекта:

.. code-block:: text

   GET /v1/alarms/?parentId=123e4567-e89b-12d3-a456-426614174000&fired=false&count=10

Активные алярмы перечисленных объектов и всех их детей:

.. code-block:: text

   GET /v1/alarms/?parentId=123e4567-e89b-12d3-a456-426614174000&parentId=123e4567-e89b-12d3-a456-426614174001&getChildren=true

Активные алярмы объекта и тега. Первый ``parentId`` — объект, второй — тег:

.. code-block:: text

   GET /v1/alarms/?parentId=123e4567-e89b-12d3-a456-426614174000&parentId=123e4567-e89b-12d3-a456-426614174002

Проверка, активна ли тревога. ``parentId`` здесь — идентификатор самой тревоги:

.. code-block:: text

   GET /v1/alarms/?parentId=123e4567-e89b-12d3-a456-426614174003

Активные алярмы объекта, старт которых не раньше 1 января 2026:

.. code-block:: text

   GET /v1/alarms/?parentId=123e4567-e89b-12d3-a456-426614174000&start=2026-01-01T00:00:00Z

Активные на 10 января 2026 алярмы объекта, старт которых не раньше 1 января:

.. code-block:: text

   GET /v1/alarms/?parentId=123e4567-e89b-12d3-a456-426614174000&start=2026-01-01T00:00:00Z&finish=2026-01-10T00:00:00Z

Все срабатывания объекта со стартом не раньше 1 января и не позднее 10 января:

.. code-block:: text

   GET /v1/alarms/?parentId=123e4567-e89b-12d3-a456-426614174000&start=2026-01-01T00:00:00Z&finish=2026-01-10T00:00:00Z&fired=false

Все срабатывания объекта со стартом не раньше 1 января 2026:

.. code-block:: text

   GET /v1/alarms/?parentId=123e4567-e89b-12d3-a456-426614174000&start=2026-01-01T00:00:00Z&fired=false

Алярмы объекта, которые были активны 1 января 2026:

.. code-block:: text

   GET /v1/alarms/?parentId=123e4567-e89b-12d3-a456-426614174000&finish=2026-01-01T00:00:00Z

Состояние всех тревог объекта на 1 января 2026:

.. code-block:: text

   GET /v1/alarms/?parentId=123e4567-e89b-12d3-a456-426614174000&finish=2026-01-01T00:00:00Z&fired=false

По 10 последних записей по каждой тревоге объекта на 1 января 2026:

.. code-block:: text

   GET /v1/alarms/?parentId=123e4567-e89b-12d3-a456-426614174000&finish=2026-01-01T00:00:00Z&count=10&fired=false

Квитирование — ``PUT /v1/alarms/``. Если ``x`` не передан, берётся текущий
момент. Повторное квитирование ничего не меняет.

.. code-block:: text

   PUT /v1/alarms/
   {"id": "<id тревоги>"}

Конфигуратор (:ref:`configurator`) берёт этот список с ``fired=false``
и квитирует тем же ``PUT``. В списке он показывает только активные
и пропавшие, но ещё не квитированные. Пропавшая и уже квитированная
в ответ приходит со всеми тремя метками, но список и кружок её не рисуют.
Сами срабатывания читаются с ``fired=false`` и ``count`` или ``start``.

Список срабатываний одной тревоги — те же поля, по ряду на эпизод:

.. code-block:: text

   GET /v1/alarms/?parentId=<id тревоги>&fired=false&count=2&format=true

.. code-block:: json

   {"data": [{
     "id": "<id тревоги>",
     "cn": "Высокий уровень",
     "description": "",
     "tagId": "<id тега>",
     "fired": "2026-11-17T19:10:58.571809+03:00",
     "finish": "2026-11-17T19:12:16.078625+03:00",
     "acked": "2026-11-17T19:15:00.000000+03:00"
   }]}

На вкладке **Хранилище** тревоги в Конфигураторе тот же запрос собран
как чтение истории тега: строка ``GET``, ключи ``format``, ``fired``,
``start``, ``finish``, ``count`` и иконка «Читать данные».
Пока ``fired`` включён, в ответе не больше одного эпизода — того,
что активно в момент ``finish``.

История значений тега запрашивается через ``GET /v1/data/``. Идентификатор
тревоги для этого запроса не годится: ответ ``422`` и пояснение, что события
тревоги читаются через ``GET /v1/alarms/?parentId=``.
