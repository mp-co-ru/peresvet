Хранилища данных
================

Хранилище данных — база, в которой лежит история значений тегов и эпизоды
тревог. Тег сам ничего не хранит: пока он не привязан к хранилищу (или
к методу чтения), прочитать его историю нельзя.

Типы хранилищ
-------------

.. list-table::
   :header-rows: 1
   :widths: 8 24 68

   * - Код
     - Тип
     - Для чего
   * - ``0``
     - PostgreSQL
     - История тегов и эпизоды тревог. Рекомендуется для промышленной
       автоматизации.
   * - ``1``
     - VictoriaMetrics
     - История числовых тегов в базе временных рядов. Драйвер есть
       в исходном коде, но в стандартную поставку не входит: ни база,
       ни драйвер ``./run_one_app.sh`` не запускает.
   * - ``2``
     - Интеграционное
     - Чтение и запись тегов запросами SQL к внешней базе, например ERP.
       См. :ref:`integrational_v2`.
   * - ``3``
     - Видеоархив
     - Каталог и срок хранения записей видеокамер. См. :ref:`video_cameras`.

Платформа работает с несколькими хранилищами одновременно, в том числе
разных типов.

Хранилище из поставки
---------------------

Стандартная поставка запускает PostgreSQL в контейнере ``prs-psql``
и заводит в модели хранилище ``psql``, подключённое к нему. Оно отмечено
как хранилище по умолчанию. Для начала работы другие хранилища не нужны.

Новое хранилище
---------------

#. В конфигураторе в меню папки «Хранилища данных» выберите
   **Новое хранилище**.
#. Задайте имя, код типа и конфигурацию подключения.
#. Нажмите **Записать**.

Конфигурация PostgreSQL — строка подключения:

.. code-block:: json

   {"dsn": "postgres://<пользователь>:<пароль>@<сервер>:5432/<база>"}

Сервер платформы должен иметь сетевой доступ к этой базе. Конфигурации
остальных типов описаны в справочнике: :doc:`dataStorages_api_doc`.

Хранилище по умолчанию
~~~~~~~~~~~~~~~~~~~~~~

Одно из хранилищ отмечают признаком «по умолчанию». Если в настройках
конфигуратора включена привязка к хранилищу по умолчанию, новый тег
и новая тревога сразу привязываются к нему.

Привязка тегов и тревог
-----------------------

В конфигураторе хранилище выбирают на вкладке **Хранилище** в свойствах
тега или тревоги. Привязанные узлы видны и в дереве: под каждым
хранилищем перечислены его теги и тревоги, путь к ним указан через
стрелку ``→``.

При привязке хранилище заводит место для данных: в PostgreSQL — таблицу
``t_<id тега>`` для тега и ``a_<id тревоги>`` для тревоги.

.. warning::

   При отвязке хранилище удаляет таблицу вместе с историей. Конфигуратор
   отвязывает узел от прежнего хранилища, когда на вкладке **Хранилище**
   выбирают другое: история в прежнем хранилище при этом пропадает,
   а в новое она не переносится.

Через API тег можно привязать к нескольким хранилищам сразу: значения
пишутся в каждое из них. Конфигуратор показывает и меняет одну привязку.

Хранилище или метод
~~~~~~~~~~~~~~~~~~~

На чтение тега отвечает хранилище, а если у тега есть метод чтения —
и метод тоже. Платформа берёт первый пришедший ответ, поэтому тег
с методом чтения или записи к хранилищу обычно не привязывают.
Конфигуратор отмечает такое сочетание восклицательным знаком.
Подробно — в разделе :doc:`methods`.

Что хранится
------------

Каждое значение тега хранится точкой: метка времени, значение и код
качества. Как читать историю и что означают ключи запроса, описано
в разделе :ref:`historical_data`.

Не каждое значение, присланное в тег, попадает в хранилище. Значения,
которые отличаются от последнего записанного меньше чем на значимое
отклонение тега, отбрасываются (см. :doc:`tags`).

Эпизоды тревог описаны в разделе :ref:`alerts_guide`.
