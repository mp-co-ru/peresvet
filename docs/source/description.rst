Описание
--------

**МПК-Пересвет** — платформа для построения моделей технических объектов.
Модель описывает, из чего состоит объект, какие у него параметры и как он
себя ведёт. На её основе платформа собирает данные с оборудования, хранит
историю, считает производные величины, следит за тревогами и запускает
действия по событиям и расписанию.

Где применяется:

#. Промышленная автоматизация: SCADA, диспетчеризация и мониторинг, MES.
#. Умный дом и умное здание.
#. Программно-аппаратные комплексы, в которых нужна своя модель объекта.

Из чего строится модель
^^^^^^^^^^^^^^^^^^^^^^^

Основа модели — иерархия. В ней лежат **объекты** (предприятие, цех,
агрегат, датчик), у объектов — **теги** (температура, давление, ток),
у тегов — **тревоги** и **методы**. Рядом с объектами в той же иерархии
описана информационная система: **коннекторы**, которые приносят данные
с оборудования, **хранилища данных**, где лежит история тегов,
и **расписания**, которые запускают задачи по времени.

Поведение модели задают методы. Метод — программа, которую платформа
вызывает, когда меняется тег или срабатывает расписание. Методы считают
значения вычисляемых тегов, проверяют сложные условия тревог, отвечают
на чтение и запись тегов, обращаются к внешним системам.

Термины подробно разобраны в разделе :ref:`terms`.

Как выглядит работа с платформой
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

#. Платформу ставят на сервер с Docker одной командой (:ref:`installation`).
#. В браузере открывают Grafana. Главная панель Grafana —
   :ref:`конфигуратор <configurator>`: в нём собирают иерархию объектов
   и тегов, настраивают коннекторы, хранилища, тревоги и методы.
#. Коннекторы, установленные рядом с оборудованием, начинают присылать
   значения тегов (:ref:`connectors_guide`). Видеокамеры подключаются так же,
   коннектором (:ref:`video_cameras`).
#. История тегов попадает в хранилище данных и читается запросом
   ``GET /v1/data/`` (:ref:`historical_data`).
#. Экраны мониторинга строятся в той же Grafana
   (:doc:`grafana/grafana_integration`). Внешние системы работают
   с платформой через :ref:`HTTP API <api>`.

Пошаговое построение модели с нуля разобрано в
`базовом курсе <https://github.com/mp-co-ru/prs-peresvet-courses/tree/main/01.base>`_.

Редакции
^^^^^^^^

Есть две редакции платформы: открытая и промышленная. Функции модели,
сбора и хранения данных у них общие. Открытая редакция не проверяет права
доступа: любой клиент, которому доступен адрес платформы, может выполнить
любой запрос. Промышленная редакция подключает аутентификацию и
авторизацию через точку расширения ядра, см.
:doc:`security_extension_points` и :doc:`security_enterprise_setup`.
