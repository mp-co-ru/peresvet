Узлы модели: общие правила
~~~~~~~~~~~~~~~~~~~~~~~~~~

Объекты, теги, тревоги, методы, коннекторы, расписания и хранилища данных
создаются, читаются, изменяются и удаляются одинаковыми запросами. Меняется
только адрес:

.. list-table::
   :header-rows: 1
   :widths: 30 30 40

   * - Сущность
     - Адрес
     - Корень ветки по умолчанию
   * - Объекты
     - ``/v1/objects/``
     - ``objects``
   * - Теги
     - ``/v1/tags/``
     - ``tags``
   * - Тревоги
     - ``/v1/alerts/``
     - — (тревога всегда лежит под тегом)
   * - Методы
     - ``/v1/methods/``
     - ``methods`` (каталог методов)
   * - Коннекторы
     - ``/v1/connectors/``
     - ``connectors``
   * - Расписания
     - ``/v1/schedules/``
     - ``schedules``
   * - Хранилища данных
     - ``/v1/dataStorages/``
     - ``dataStorages``

Здесь описаны общие правила. Особенности каждой сущности — на её странице.

Общие атрибуты
--------------

Свойства узла передаются в объекте ``attributes``. У всех сущностей есть
такие атрибуты:

.. list-table::
   :header-rows: 1
   :widths: 26 74

   * - Атрибут
     - Смысл
   * - ``cn``
     - Имя узла. Должно быть уникальным среди узлов с тем же родителем.
       Если имя не задано, узел получает имя, равное своему идентификатору.
   * - ``description``
     - Описание. Конфигуратор показывает его в подсказке к узлу.
   * - ``prsActive``
     - Признак «Активный». ``false`` выключает узел: выключенный тег
       не читается и не пишется, выключенная тревога не проверяется,
       выключенный коннектор не опрашивает источник. По умолчанию ``true``.
   * - ``prsJsonConfigString``
     - Конфигурация узла — объект JSON. Её формат зависит от сущности.
       Строка с JSON тоже принимается.
   * - ``prsEntityTypeCode``
     - Код типа. Смысл зависит от сущности: тип метода, тип хранилища,
       камера среди коннекторов.
   * - ``prsIndex``
     - Порядковый номер. Узлы одного родителя возвращаются отсортированными
       по нему.
   * - ``prsDefault``
     - Узел по умолчанию среди соседей того же вида. Так задаётся
       хранилище по умолчанию. Первый узел на уровне становится узлом
       по умолчанию сам. Если создать узел с ``prsDefault: true``, прежний
       узел по умолчанию этот признак теряет. При изменении узла запросом
       ``PUT`` прежний признак не снимается: снимите его отдельно.

Создание
--------

``POST /v1/<сущность>/``

.. code-block:: json

   {
     "parentId": "<id родителя>",
     "attributes": {
       "cn": "Насос 1",
       "description": "Насос подачи воды"
     }
   }

* ``parentId`` — родитель нового узла. Если не задан, узел создаётся
  в корне ветки своей сущности. Какие родители допустимы, указано
  на странице сущности.
* ``attributes`` — атрибуты нового узла. Незаданные атрибуты получают
  значения по умолчанию.
* ``folder`` — ``true`` создаёт не узел сущности, а папку
  (см. :doc:`folders`). По умолчанию ``false``.

Ответ ``201``:

.. code-block:: json

   {"id": "2e9c3c5a-0f6b-103f-8a4b-27c2f0a7d6e1"}

Если у родителя уже есть узел с таким именем, ответ — ``422`` «Ошибка
создания узла».

Чтение
------

``GET /v1/<сущность>/``

.. list-table::
   :header-rows: 1
   :widths: 18 62 20

   * - Параметр
     - Смысл
     - По умолчанию
   * - ``id``
     - Идентификатор узла или список идентификаторов. Если задан,
       ``base``, ``scope`` и ``filter`` не учитываются.
     - —
   * - ``base``
     - Узел, от которого ведётся поиск: идентификатор, ``prs`` (корень
       всей модели) или имя корня ветки — ``objects``, ``tags``,
       ``connectors``, ``schedules``, ``dataStorages``, ``methods``.
     - корень ветки сущности
   * - ``scope``
     - Глубина поиска: ``0`` — сам узел ``base``; ``1`` — его прямые
       потомки; ``2`` — всё поддерево.
     - ``1``
   * - ``filter``
     - Отбор по атрибутам — объект JSON, где каждому атрибуту
       соответствует список допустимых значений. Значения одного атрибута
       объединяются через «или», разные атрибуты — через «и». Знак ``*``
       заменяет любые символы: ``{"cn": ["Насос*"]}``.
     - —
   * - ``attributes``
     - Какие атрибуты вернуть. ``*`` — все.
     - ``cn``
   * - ``hierarchy``
     - Вместе со ``scope=2`` возвращает дерево: у каждого узла есть
       список потомков ``children``, папки тоже обходятся.
     - ``false``
   * - ``getParent``
     - Добавить каждому узлу поле ``parentId``. Для узла в корне ветки
       ``parentId`` равен ``null``.
     - ``false``
   * - ``deref``
     - Раскрывать ссылки LDAP (псевдонимы) при поиске. Обычно не меняют.
     - ``true``

Без параметров запрос возвращает узлы, лежащие прямо в корне ветки
сущности. Например, ``GET /v1/tags/`` вернёт теги из папки «Теги», но не
теги объектов. Чтобы найти узлы во всей модели, задайте ``base=prs``
и ``scope=2``. Узел внутри пользовательской папки не является прямым
потомком родителя папки: его возвращает только ``scope=2``.

Пример — все активные теги модели с типом значения:

.. code-block:: text

   GET /v1/tags/?base=prs&scope=2&filter={"prsActive":[true]}&attributes=cn&attributes=prsValueTypeCode

Ответ ``200``:

.. code-block:: json

   {
     "data": [
       {
         "id": "2e9c3c5a-0f6b-103f-8a4b-27c2f0a7d6e1",
         "dn": "cn=Температура,cn=Насос 1,cn=objects,cn=prs",
         "attributes": {
           "cn": ["Температура"],
           "prsValueTypeCode": ["1"]
         }
       }
     ]
   }

Значения атрибутов приходят так, как их хранит LDAP: каждое значение —
список строк. Логические значения — строки ``"TRUE"`` и ``"FALSE"``,
конфигурация ``prsJsonConfigString`` — строка с JSON. Если у узла нет
запрошенного атрибута, приходит ``[null]``. Если ничего не найдено,
``data`` — пустой список.

Изменение и перенос
-------------------

``PUT /v1/<сущность>/``

.. code-block:: json

   {
     "id": "<id узла>",
     "attributes": {"cn": "Насос 2", "prsActive": false},
     "parentId": "<id нового родителя>"
   }

* ``attributes`` — только те атрибуты, которые нужно изменить.
* ``parentId`` — необязательный. Если задан, узел вместе со всей своей
  веткой переносится к новому родителю. Вместо идентификатора можно указать
  имя корня ветки (``objects``, ``tags`` и т.д.). Перенести узел внутрь
  его собственной ветки нельзя.

Ответ ``202`` — пустой объект.

Признак ``prsActive`` меняется только у самого узла. Его потомки остаются
в прежнем состоянии.

Удаление
--------

``DELETE /v1/<сущность>/``

.. code-block:: json

   {"id": ["<id1>", "<id2>"]}

``id`` — идентификатор или список. Узел удаляется вместе со всеми
потомками: удаление объекта удаляет его теги, их тревоги и методы.
Ответ ``202``.

Копирование
-----------

``POST /v1/<сущность>/copy`` — для объектов, тегов, тревог и методов.

.. code-block:: json

   {
     "sourceId": "<id копируемого узла>",
     "parentId": "<id родителя копии>",
     "attributes": {"cn": "Насос 2"}
   }

Копия создаётся вместе со всеми потомками. ``attributes`` необязательны:
в них задают, например, имя копии. Если имя занято, платформа добавит
к нему «(копия)», «(копия 2)» и т.д.

Ссылки внутри копируемой ветки указывают на новые узлы: метод в копии
объекта читает теги копии, а не оригинала. Ссылки на узлы вне ветки
остаются прежними. Копия привязана к тем же хранилищам, что и оригинал,
а к коннекторам не привязана: два тега не должны читать один и тот же
адрес источника.

Тот же результат даёт запрос создания ``POST /v1/<сущность>/``
с полем ``sourceId``. Коннектор копируется только так,
см. :doc:`connectors`. Ответ ``201`` с идентификатором копии.
