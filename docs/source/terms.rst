.. _terms:

Терминология
------------

**Модель технического объекта** — статическая модель (из чего состоит объект)
вместе с динамической (как он себя ведёт).

**Статическая модель** — иерархия сущностей. Кроме самого объекта, в неё
входят сущности информационной системы: коннекторы, хранилища, расписания.
В простейшем случае статическая модель — линейный список тегов без объектов.

**Динамическая модель** — набор методов. Методы описывают процессы на объекте
и считают значения вычисляемых тегов. Платформа запускает их по событиям
модели.

.. _entity:

**Сущность** — тип узла иерархии. Основные сущности модели объекта: объекты,
теги, тревоги, методы, расписания. Сущности информационной системы:
коннекторы и хранилища данных. Каждому типу соответствует класс LDAP
с префиксом ``prs``: ``prsObject``, ``prsTag``, ``prsAlert`` и т.д.
Платформу можно расширять собственными сущностями со своей логикой.

**Объект** — основной элемент иерархии: предприятие, цех, участок,
технологическая линия, агрегат, датчик. Объект может содержать любое число
дочерних объектов и тегов.

**Тег** — параметр объекта: температура, давление, сила тока и т.п.
Значения тега хранятся в хранилище данных. У каждого значения есть метка
времени и код качества (см. :ref:`qualityCodes`).
Тег обычно лежит под объектом, но может лежать и в общем списке тегов
без объекта.

Типы значений тега: целый, вещественный, строковый, JSON, интеграционный
и видеопоток. Значения интеграционного тега читаются и пишутся запросами
к внешней базе (:ref:`integrational_v2`). Кадры видеопотока в историю тегов
не пишутся (:ref:`video_cameras`).

.. warning:: Хранилище VictoriaMetrics коды качества не хранит.

**Папка** — узел для группировки других узлов в дереве (класс ``prsFolder``).
Папка ничего не вычисляет и ни на что не влияет: она только помогает
разложить объекты, теги, коннекторы, расписания, хранилища и методы
каталога по смысловым группам.

**Событие** — то, на что реагирует модель. Основных событий три: новое
значение тега, возникновение тревоги, срабатывание расписания. К событиям
привязывают методы, и модель «оживает».

**Тревога** — состояние тега, которое возникает, когда значение тега
выполняет заданное условие. В автоматизации обычно используют четыре уровня:
LoLo, Lo, Hi, HiHi.

| Пример: рыбкам в аквариуме комфортно при температуре воды от 20 до 25 °C,
| а ниже 15 °C и выше 30 °C — опасно. К тегу температуры воды привязывают
| четыре тревоги: LoLo = 15 °C, Lo = 20 °C, Hi = 25 °C, HiHi = 30 °C.
| Тревога Lo или Hi говорит, что вода вышла из комфортного диапазона и пора
| поправить нагрев. Тревога LoLo или HiHi требует срочных мер.

В МПК-Пересвет у тега может быть сколько угодно тревог. Условием тревоги
может быть не только порог, но и результат метода: так строят сложные
тревоги, учитывающие значения других тегов.

**Метод** — программный код, который реализует поведение модели. Метод
вызывается по событию и, например, считает значение тега, решает,
возникла ли тревога, или вызывает внешний процесс. Подробно —
в разделе :doc:`methods`.

**Расписание** — генератор событий по времени. По событию расписания
запускаются методы: расчёт тегов, формирование отчётов, рассылки.

**Хранилище данных** — база, в которой лежит история значений тегов
и тревог. Платформа одновременно работает с несколькими хранилищами разных
типов. Для промышленной автоматизации рекомендуется PostgreSQL, есть также
драйвер VictoriaMetrics, интеграционное хранилище для внешних реляционных
баз и хранилище видеоархива. Для других баз можно написать свой драйвер.

.. _definition_connector:

**Коннектор** — программа, которая читает данные устройства по определённому
протоколу и передаёт их в платформу. Обычно на каждый протокол пишут свой
коннектор. См. :ref:`connectors_guide`.

**Константа** — значение, общее для всей модели, которое можно передать
в метод (класс ``prsConstant``). Отдельного API для констант пока нет.
