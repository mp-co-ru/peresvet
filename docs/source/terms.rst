.. _terms:

Терминология
------------

Модель
^^^^^^

**Модель технического объекта** — описание того, из чего состоит объект
(статическая модель) и как он себя ведёт (динамическая модель).

**Статическая модель** — иерархия узлов: объекты, теги, тревоги, а рядом
с ними — сущности информационной системы: коннекторы, хранилища,
расписания. В простейшем случае статическая модель — линейный список тегов
без объектов.

**Динамическая модель** — набор методов. Методы описывают процессы
на объекте и считают значения вычисляемых тегов. Платформа запускает их
по событиям модели.

.. _entity:

**Сущность** — вид узла иерархии. Каждой сущности соответствует класс
LDAP с префиксом ``prs``: ``prsObject``, ``prsTag``, ``prsAlert`` и т.д.
Платформу можно расширять собственными сущностями со своей логикой.

**Узел** — один элемент иерархии: конкретный объект, тег, тревога.
У каждого узла есть имя и неизменный идентификатор (GUID).

Сущности модели объекта
^^^^^^^^^^^^^^^^^^^^^^^

**Объект** — основной элемент иерархии: предприятие, цех, участок,
технологическая линия, агрегат, датчик. Объект может содержать любое число
вложенных объектов и тегов.

**Тег** — параметр объекта: температура, давление, сила тока и т.п.
Тег обычно лежит в объекте, но может лежать и в общем списке тегов
без объекта. Значения тега — это его история: у каждого значения есть
метка времени и код качества (:ref:`qualityCodes`). Типы значений: целое,
вещественное, строка, JSON, интеграционный (значения лежат во внешней
базе, :ref:`integrational_v2`) и видеопоток (:ref:`video_cameras`).

**Тревога** — правило, которое следит за значением тега и срабатывает,
когда оно выходит за порог. У тега может быть сколько угодно тревог.
Срабатывание, пропадание и квитирование тревоги вместе называются
**эпизодом**. Подробно — в разделе :ref:`alerts_guide`.

**Квитирование** — подтверждение оператора, что он увидел тревогу.

**Метод** — программа, которую платформа вызывает по событию: считает
значение тега, отвечает на чтение или запись тега, обращается к внешней
системе. Подробно — в разделе :doc:`methods`.

**Инициатор** — тег, расписание или тревога, событие которых запускает
вычислительный метод.

**Папка** — узел для группировки других узлов в дереве (класс
``prsFolder``). Папка ничего не вычисляет и ни на что не влияет: она
только помогает разложить объекты, теги, коннекторы, расписания,
хранилища и методы каталога по смысловым группам.

**Константа** — значение, общее для всей модели, которое можно передать
в метод (класс ``prsConstant``). Отдельного API для констант пока нет.

Сущности информационной системы
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

.. _definition_connector:

**Коннектор** — программа, которая читает данные устройства
по определённому протоколу и передаёт их в теги платформы. Обычно
на каждый протокол пишут свой коннектор. Подробно — в разделе
:ref:`connectors_guide`.

**Хранилище данных** — база, в которой лежит история значений тегов
и эпизоды тревог. Платформа работает с несколькими хранилищами
одновременно. В стандартной поставке — PostgreSQL; есть также
интеграционные хранилища для внешних баз и видеоархив. Подробно —
в разделе :ref:`storages_guide`.

**Расписание** — генератор событий по времени. По событию расписания
запускаются методы: расчёт тегов, формирование отчётов, рассылки.
Подробно — в разделе :ref:`schedules_guide`.

События
^^^^^^^

**Событие** — то, на что реагирует модель: новое значение тега,
срабатывание, пропадание или квитирование тревоги, срабатывание
расписания. К событиям привязывают методы, и модель «оживает».
