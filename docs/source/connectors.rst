Коннекторы
~~~~~~~~~~

Назначение коннекторов, их настройка и журнал описаны в разделе
:ref:`connectors_guide`. Здесь — протокол обмена коннектора с платформой
для тех, кто пишет свой коннектор без пакета
`prs-connector-core <https://github.com/mp-co-ru/prs-connector-core>`__,
и справочник CRUD API коннекторов.

Протокол обмена
---------------

Коннектор подключается к брокеру RabbitMQ платформы по MQTT (порт ``1883``).
Сообщения MQTT попадают в обменник ``peresvet``, где их принимает сервис
``connectors_mqtt_app``.

* **ClientId** MQTT-сессии должен совпадать с UUID узла коннектора
  в платформе. По нему платформа сопоставляет сессию брокера с коннектором.
* Коннектор публикует сообщения в топик ``conn2prs/<id коннектора>``.
* Платформа отправляет коннектору сообщения в топик
  ``prs2conn/<id коннектора>``.

Порядок работы после подключения:

#. Сразу после подключения коннектор может отправить значения, накопленные
   в буфере без связи. У них метки времени до восстановления связи.
#. Коннектор запрашивает конфигурацию (``getConfig``).
#. На первый запрос конфигурации в новой сессии платформа пишет во все теги
   коннектора ``null`` с кодом качества 101, дожидается подтверждения
   записи и только потом отправляет ``prsConnector.full_configuration``.
   Повторный запрос в той же сессии 101 не пишет.
#. Получив конфигурацию, коннектор читает **все** привязанные теги и
   отправляет их значения, даже если они не изменились. До получения
   конфигурации текущие значения слать нельзя: они окажутся в истории
   раньше отметки 101, и текущим значением тега останется ``null``.

Потеря связи
------------

При любом закрытии MQTT-сессии — штатном отключении, обрыве TCP, истечении
keepalive — брокер публикует событие ``connection.closed`` в обменник
``amq.rabbitmq.event``. Сервис ``connectors_mqtt_app`` получает его
по AMQP и пишет во все теги коннектора ``null`` с кодом качества 100.
Повторная запись 100 подряд отсекается. После этого следующий запрос
конфигурации снова запишет 101.

Дополнительно коннектор при подключении задаёт Last Will:

* топик — ``prsConnector/connection_lost/<id коннектора>``;
* тело — ``{"id": "<id коннектора>"}``.

Если коннектор пропал нештатно, брокер публикует это сообщение, и платформа
обрабатывает его так же, как ``connection.closed``. ``BaseConnector``
настраивает Last Will сам.

Камеры
------

Коннектор-камера (с ключом ``rtspUrl`` в ``source`` или с кодом типа
``prsEntityTypeCode = 10``) этим протоколом не пользуется. MQTT-сессию
с ClientId камеры открывает сервис захвата видео, пока держит соединение
с камерой, и закрывает её вместе с соединением. По событиям этой сессии
платформа только показывает состояние связи в дереве: коды 100 и 101
в теги камеры не пишутся, ``full_configuration`` не отправляется.
Журнал у камеры такой же, как у других коннекторов. Подробно — в
:ref:`video_cameras`.

Сервисный API коннекторов
-------------------------

Кроме CRUD, сервис ``connectors_app_api`` предоставляет такие запросы:

* ``POST /v1/connectors_app/`` — отправить коннектору удалённые команды
  (см. :ref:`connectors_guide`);
* ``GET /v1/connectors_app/link_status?id=<id>`` — есть ли сейчас
  MQTT-сессия коннектора;
* ``GET /v1/connectors_app/log_tail?id=<id>`` — последние строки журнала
  коннектора, присланные в платформу;
* ``GET /v1/connectors_app/command_output_tail?id=<id>`` — последние
  результаты удалённых команд;
* ``GET /v1/connectors_app/services`` и
  ``GET /v1/connectors_app/service_log_tail?service=<имя>`` — сервисы
  платформы и их журналы (блок «Сервисы» конфигуратора).
