Коннекторы

Как работают коннекторы, как их настраивать и читать их журнал, описано в разделе Коннекторы. Здесь — запросы к коннекторам и протокол обмена для тех, кто пишет свой коннектор без пакета prs-connector-core.

Узлы коннекторов

Адрес — /v1/connectors/. Запросы те же, что у всех узлов модели (Узлы модели: общие правила). Родитель коннектора — пользовательская папка в ветке коннекторов; без parentId коннектор создаётся в корне ветки.

Конфигурация коннектора

prsJsonConfigString коннектора состоит из двух блоков:

  • source — как подключиться к источнику. Формат задаёт конкретный коннектор;

  • log — журнал: level, fileName, maxBytes, backupCount, sendToPlatform (см. Коннекторы).

prsEntityTypeCode = 10 или ключ source.rtspUrl означают камеру (Подключение видеокамер).

Привязка тегов

Теги привязывают полем linkedTags в запросах POST и PUT:

{
  "id": "<id коннектора>",
  "linkedTags": [
    {
      "tagId": "<id тега>",
      "attributes": {
        "prsJsonConfigString": {
          "source": {"register": 40001},
          "maxDev": 0.1,
          "JSONata": "$ / 10",
          "frequency": 1
        }
      }
    }
  ],
  "unlinkTags": ["<id другого тега>"]
}

Ключи prsJsonConfigString привязки:

Ключ

Смысл

По умолчанию

source

Где взять значение тега в источнике: адрес регистра, топик и т.п. Формат задаёт коннектор.

{}

maxDev

Значимое отклонение: коннектор не отправляет значение, если оно отличается от последнего отправленного меньше чем на эту величину.

0

JSONata

Выражение JSONata, которое применяется к прочитанному значению.

—

frequency

Период опроса тега в секундах (для коннекторов, которые сами опрашивают источник).

5

  • linkedTags в PUT добавляет теги или меняет параметры уже привязанных.

  • unlinkTags — список идентификаторов тегов, которые нужно отвязать.

  • GET /v1/connectors/?getLinkedTags=true возвращает у каждого коннектора список linkedTags с параметрами привязок.

Обычно тег привязывают к одному коннектору: конфигуратор предлагает выбрать один. API не запрещает несколько привязок, но тогда тег получает значения от каждого коннектора вперемешку.

Копирование

Коннектор копируется запросом создания с полем sourceId:

POST /v1/connectors/

{
  "sourceId": "<id коннектора>",
  "copyLinkedTags": false,
  "attributes": {"cn": "Счётчик 2"}
}

copyLinkedTags: true привязывает к копии те же теги с теми же параметрами. Пока одну из привязок не снимут, каждый такой тег получает значения от обоих коннекторов.

Сервисные запросы

Адрес — /v1/connectors_app/.

Запрос

Что делает

POST /v1/connectors_app/

Отправляет коннектору команды оболочки (см. ниже).

GET /v1/connectors_app/link_status?id=<id>

Есть ли связь с коннектором: {"id": "...", "mqttConnected": true}.

GET /v1/connectors_app/log_tail?id=<id>

Последние строки журнала, которые коннектор прислал в платформу: {"id": "...", "entries": [...]}.

GET /v1/connectors_app/command_output_tail?id=<id>

Последние результаты удалённых команд.

GET /v1/connectors_app/services

Список сервисов платформы (блок «Сервисы» конфигуратора).

GET /v1/connectors_app/service_log_tail?service=<имя>&limit=400

Последние строки журналов сервисов. service можно повторить несколько раз, limit — от 1 до 2000 строк на сервис.

DELETE /v1/connectors_app/service_log_tail?service=<имя>

Очищает журналы выбранных сервисов в памяти платформы.

Удалённые команды

{
  "id": "<id коннектора>",
  "command": {
    "lines": ["ping -c 3 192.168.1.50", "df -h"],
    "timeoutSec": 60
  }
}

Ключи command:

  • lines — команды оболочки, каждая строка выполняется отдельно;

  • timeoutSec — ограничение времени на одну строку, по умолчанию 120 секунд;

  • maxOutputBytes — сколько байт вывода сохранять, по умолчанию 65536;

  • logToPlatform — включить (true) или выключить (false) передачу журнала коннектора в платформу.

Ответ {"ok": true, "message": "Команда принята к доставке коннектору."} означает, что команда передана брокеру. Результаты приходят позже, их читают запросом command_output_tail. Если доставить команду некому, ответ — 424.

Предупреждение

Команды выполняются на машине коннектора с правами его процесса. В открытой редакции платформа не проверяет, кто их отправляет.

Протокол обмена

Коннектор подключается к брокеру RabbitMQ платформы по MQTT (порт 1883). Сообщения MQTT попадают в обменник peresvet, где их принимает сервис connectors_mqtt_app.

  • ClientId MQTT-сессии должен совпадать с идентификатором узла коннектора. По нему платформа понимает, какой коннектор подключился.

  • Коннектор публикует сообщения в топик conn2prs/<id коннектора>.

  • Платформа отправляет коннектору сообщения в топик prs2conn/<id коннектора>.

Порядок работы после подключения:

  1. Сразу после подключения коннектор может отправить значения, накопленные в буфере без связи. У них метки времени до восстановления связи.

  2. Коннектор запрашивает конфигурацию (getConfig).

  3. На первый запрос конфигурации в новой сессии платформа пишет во все теги коннектора null с кодом качества 101, дожидается подтверждения записи и только потом отправляет prsConnector.full_configuration. Повторный запрос в той же сессии 101 не пишет.

  4. Получив конфигурацию, коннектор читает все привязанные теги и отправляет их значения, даже если они не изменились. До получения конфигурации текущие значения слать нельзя: они окажутся в истории раньше отметки 101, и текущим значением тега останется null.

Потеря связи

При любом закрытии MQTT-сессии — штатном отключении, обрыве TCP, истечении keepalive — брокер публикует событие connection.closed в обменник amq.rabbitmq.event. Сервис connectors_mqtt_app получает его и пишет во все теги коннектора null с кодом качества 100. Повторная запись 100 подряд не делается. Следующий запрос конфигурации снова запишет 101.

Кроме того, коннектор при подключении задаёт Last Will:

  • топик — prsConnector/connection_lost/<id коннектора>;

  • тело — {"id": "<id коннектора>"}.

Если коннектор пропал нештатно, брокер публикует это сообщение, и платформа обрабатывает его так же, как connection.closed. BaseConnector из prs-connector-core настраивает Last Will сам.

Камеры

Коннектор-камера этим протоколом не пользуется. MQTT-сессию с ClientId камеры открывает сервис захвата видео, пока держит соединение с камерой, и закрывает её вместе с соединением. По этой сессии конфигуратор только показывает состояние связи: коды 100 и 101 в теги камеры не пишутся, full_configuration не отправляется. Подробно — в разделе Подключение видеокамер.
